# 本地财报库兼容接入

日期：2026-10-15。完成增量合并，无需运行原交付包安装器。

## 生效方式

重启原后端，再刷新网页即可。前端不需要重装依赖。现有历史记录仍为原始快照，不会自动重算；从报告发起新的历史回溯、同行计算或创建新公开报告任务，即可使用本地库。

库内共 133 份 PDF、28 家有财报的公司，目录共 54 家，年份覆盖 2021—2025。与既有公司搜索目录合并，不移除既有候选。2025 年报告向前回溯 5 年会请求 2020—2024；本地库没有 2020 年，缺失年度按联网配置补齐，无法取得时明确标记缺失。

## 各流程的数据来源顺序

| 操作 | 数据来源与版本 |
| --- | --- |
| 搜索并分析公开报告 | 本地财报库优先；缺失时沿用原缓存/公开披露获取流程 |
| 上传财报 | 本期仍使用用户上传的 PDF，不被库内报告替换 |
| 上传后自动回溯或手动回溯 | 用户补传和任务链已选版本优先；之后本地库、缓存、联网补齐 |
| 计算同行 | 目标仍为当前已分析报告，复用其指标和历史；只获取同行年报，本地优先 |
| 打开原文 | 只开放任务接受的文件；库内 PDF 需与任务文档及索引哈希一致 |

本地财报版本和快照日期保留在取得记录里。库内文件损坏、证券代码冲突、会计年度不符、版本选择不唯一均不会当作有效数据。缺失不补零，有 PDF 不代表已有指标，也不保证所有字段均可提取。

## 配置与检查

- 默认目录：`backend/data/report_library`。
- 可选 `FINANCE_LIBRARY_DIR` 指定其他本地库；相对路径相对于 `backend`。
- `FINANCE_LIBRARY_ALLOW_ONLINE` 默认 `1`，保留联网补齐；设置为 `0` 可禁用报告联网补齐。
- 历史回溯请求里的 `online=false` 仍然有效，不会妨碍读取本地财报。
- `GET /api/health` 的 `report_library` 可检查是否载入，当前应显示 133 份 PDF、28 家有报告的公司。
- 未修改 `.env`、模型密钥、正式历史结果或财务计算公式。
- 取消任务在文件解析前后及跨报告阶段检查；已开始的单次 PDF 解析不能即时中断，但取消后不会继续下一份报告或发布晚到结果。
