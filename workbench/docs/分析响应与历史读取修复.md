# 分析响应与历史读取修复

适用版本：`/api/health` 中 `runtime_revision = responsive-analysis-1`。

## 已调整的运行方式

- PDF 文字、年报表格、半年报/季报提取和证券代码识别在独立 Python 子进程执行。API 服务不再承担这些 CPU 密集解析。
- 同时最多两个解析进程；同一文件、同一参数和解析器版本的并发请求合并为一次解析。
- 文件 SHA-256、解析操作/参数、引擎代码、Python 和 PDF/OCR 依赖版本共同组成缓存键。缓存位于 `backend/data/history_parsed/pdf-runtime`，不跨版本直接复用旧解析。
- 单次解析内只复用相同 PDF 页的原始文字，不改变列顺序、金额、单位、证据坐标或缺失值处理。
- 解析有阶段/页码/耗时反馈；页码仅表示当前阶段，百分比不是逐页完成率。最长单次解析 15 分钟，连续 3 分钟没有阶段/页码消息会终止并给出原因。停止任务会终止该任务创建的解析子进程，不结束用户的其他 Python 服务。
- Windows 子进程明确使用 UTF-8，支持中文用户目录和文件名。

## 本期与历史独立

公开年报和本地上传均先保存本期报告，再建立独立历史回溯任务。历史失败/停止不覆盖本期报告；补齐另存版本，原文报告不重写。用户设置的回溯年限仍保存并应用。

历史任务尚未建立的等待状态只用于当前服务会话明确标记的任务。旧报告或服务重启不会因为不存在的历史任务一直轮询。

## 历史读取

历史查询使用专用线程池，并读取 `backend/data/tasks/.summaries` 中的轻量索引。索引绑定原任务文件的修改时间与大小；旧记录首次读取会生成可重建的摘要，不改写原任务或已保存财务结论。摘要损坏时从原记录恢复。

历史列表不获取分析任务写入锁。服务器 10 秒截止后返回明确错误，前端不无限等待；失败刷新保留最近成功的数据，首次未读取时统计显示“—”，不把未知显示成零条记录。

超过 2 秒的请求记录 `history_read`；超过截止时间记录 `history_timeout phase=... task=...`，区分排队、目录枚举、摘要读取、身份关联和原文件可用性检查。日志不包含报告正文和密钥。

## 启用

代码修改不会热更新已运行的 Uvicorn。停止原后端后重新启动一次即可，工作台刷新页面；无需删除数据库、PDF 或历史记录。重启前尚未完成的旧任务不会自动续跑，应确认旧任务状态后重新提交。

## 验收

`scripts/run-upload-regression.py test_runtime_responsiveness` 覆盖写入锁阻塞、服务端截止、摘要重建、任务取消/超时/崩溃、缓存复用与并发去重、本期结果提前可读和旧任务无假等待。

`scripts/check-responsive-analysis.py --real-pdf` 只在 artifacts 中复制历史快照进行验收，原财务报告只读。真实解析期间持续读取历史列表，完成后核验缓存复用。验收结果位于 `artifacts/responsive-analysis/acceptance-*`。

原服务历史请求超过 45 秒未返回，但当时没有取得挂起线程栈，不能把其唯一原因认定为某一个锁。此次移除历史查询对任务写入锁和通用工作线程的依赖、隔离 PDF 计算并增加阶段诊断；上线后的响应仍应通过新版服务验收，而不是仅凭健康检查判断所有接口正常。
