# 历史记录功能方案（待确认）

## 定位与入口

历史记录用于保存并重新打开过去执行的分析任务。例如：今天分析宁德时代2025年年报，明天重新进入网页，直接打开当时的报告、指标、风险信号和原文证据，无需再次搜索或上传。

在左侧“披露与管理”中新增“历史记录”入口，打开独立记录页面。现有“历史分析”继续用于跨年度财务趋势，两者分别承担任务管理和财务分析。

## 页面内容

页面上方展示“全部任务、已完成、待复核、失败或中断”统计卡片，下方为搜索、筛选及记录列表。记录默认按创建时间倒序，支持分页和收藏置顶。

列表字段：公司名称与证券代码、报告期间、任务类型、来源、状态、创建时间、可用指标数量、风险信号数量、数据版本和操作入口。

任务类型包括财报分析、同行比较、公告解析、扫描件复核。状态区分排队中、分析中、已完成、部分完成、待复核、失败、已中断。演示数据不进入真实历史记录。

搜索支持公司简称、证券代码及文件名；筛选支持报告年份、任务类型、状态和创建时间。

## 核心操作

| 操作 | 行为 |
| --- | --- |
| 查看结果 | 恢复该任务保存的指标、风险信号、报告和证据，不重新运行分析 |
| 查看原文件 | 打开已保存的上传PDF或下载缓存，明确显示文件缺失状态 |
| 下载 | 下载该版本的分析报告、指标Excel或A4黑白PDF；已生成文件可重新下载 |
| 重新分析 | 用原文件和保存的配置创建新任务，保留旧结果及版本 |
| 继续复核 | 恢复扫描件候选、已作决定和未完成项；公告候选显示待复核提示，实际确认流程需另行接入 |
| 收藏、备注 | 置顶重要任务，记录分析师自己的判断与复核备注 |
| 移入回收站 | 隐藏记录，允许恢复；不立即删除共享PDF缓存 |

同一公司、同一报告期可有多个版本，显示原文件SHA-256、配置、引擎版本和创建时间。新一次运行不覆盖旧结论。

## 数据保存与现有能力

现有后端已在本地保存任务信息和分析结果，也保存上传PDF和公开报告缓存，但网页尚无完整历史列表和恢复入口。首版优先复用这些数据，不需要额外安装数据库。

本地目录均位于项目backend/data内：tasks保存任务记录，results保存分析结果，uploads保存用户上传PDF，report_cache保存公开报告下载缓存。后续如果需要多人协作，再升级到SQLite或服务端数据库。

还需要为任务补充创建时的完整请求、分析配置、公司身份、原文件关联和结果摘要；旧任务缺少字段时显示“未记录”，不伪造原配置。

网页刷新或重启后应能重新读取记录。服务停止时尚未完成的任务显示“已中断”，支持手动重试，不能一直显示“分析中”或宣称可以自动续跑。

## 建议实施顺序

第一阶段：列表、搜索筛选、恢复完整结果、原文入口、Excel/PDF下载、重启后保留记录与中断状态处理。

第二阶段：收藏、备注、回收站、版本分组、继续扫描复核；按后端能力逐步补充公告确认流程。

第三阶段：批量下载、两次分析结果的版本差异比较、多人协作。

本文件只提出方案，当前网页没有新增历史记录功能，实施需用户确认。
