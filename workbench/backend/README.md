# 财务分析后端

后端端口为 `8001`，不会占用原 DCF 演示接口使用的 `8000` 端口。

主要接口：

- `GET /api/health`：服务与模型配置状态。
- `GET /api/companies?q=&report_year=2025&segment=&exclude=&offset=0&limit=20`：公司联想、业务筛选及分页；公司身份与本机该年度的数据状态独立返回。
- `GET /api/companies/lookup?code=601611&report_year=2025`：明确触发名单外六位 A 股代码的官方目录核验，不下载财报、不调用大模型。
- `POST /api/tasks/upload`：原始 PDF 文件上传并创建任务。
- `POST /api/tasks/online`：按公司和财年检索公开报告。
- `GET /api/tasks/{id}`：查询任务进度。
- `GET /api/tasks/{id}/result`：读取分析结果。
- `GET /api/tasks/{id}/evidence/{fact_id}`：读取原文证据。
- `POST /api/scan/tasks`：扫描页 OCR 候选提取。
- `POST /api/scan/{id}/review-template`：创建人工复核模板。
- `POST /api/scan/{id}/review`：提交人工复核并重新计算。

完整交互参数请启动服务后访问 `http://127.0.0.1:8001/docs`。

报告正文使用中文展示指标、表名、状态及原因；模型提示词附带中文术语表。前端对旧报告也按 `shared/reportTerms.json` 与财务指标名称表转换，网页、复制和 PDF 导出使用同一份展示文本，不改写历史原始报告或财务数据。原文 URL、PDF 文件名、哈希和事实编号保留，不进行指标代码的子串替换。更新后端提示词需重启服务；已保存报告无需重算。

## 本地财报库（兼容合并版）

`data/report_library/` 保存本地 PDF、`index.json` 和 `companies.json`。默认自动启用，不需要另行运行交付包安装器。公开报告分析与同行任务优先使用本地库；上传后的独立历史回溯优先保留用户补传及任务链已选版本，再查询本地库、缓存和公开披露。旧历史结果不会自动重算或覆盖。

本地文件使用前核对 SHA-256、PDF 标记、公司证券代码及报告年度；库内损坏文件或多版本冲突会明确报错，不静默使用另一份报告。年度缺失仍返回缺失状态，不补零、不生成虚构趋势。本地快照不保证是实时最新披露。

可选运行环境变量（此次合并未修改 `.env`）：

- `FINANCE_LIBRARY_DIR`：自定义财报库目录；相对路径以 `backend` 为基准。默认 `data/report_library`。
- `FINANCE_LIBRARY_ALLOW_ONLINE=0`：禁止报告缺失时联网补齐。默认 `1`，保持现有公开报告流程；历史回溯请求的 `online=false` 也禁止该次任务联网。本地可用的财报不会重复联网下载。名单外代码的显式官方核验入口仍为独立功能。

`GET /api/health` 的 `report_library` 返回库是否已载入、PDF 数量和快照日期。公司搜索保留原来的联想、拼音、分页及业务分类，合并库内新增公司；“已有 PDF”不等于已提取指标。原文接口只开放当前任务已接受、与文档哈希一致的库内 PDF。

重启后端后新任务即可使用本地库。重开旧历史不会自动补算，可从旧结果发起新的历史回溯或同行比较。

测试命令（从工程根目录运行）：

```powershell
& 'D:\marktext\dcf-agent-env\python.exe' -B scripts/verify_report_library.py
```

该命令用宁德时代 2025 本期、2023/2024 历史及两家同行的真实 PDF 做离线验收，不调用模型；任务与缓存写入隔离临时目录，结束后移除，只保留 `artifacts/report-library-smoke.json` 验证摘要。首次解析可能需要数分钟。此测试不代表全库全部财务字段已认证。

## 同行公司库

报告身份统一由 `report_identity.py` 处理。新上传文件自动读取明确的六位证券代码；已保存文档、同一 PDF 的已完成历史/同行任务可复用核验结果，无需重复输入。找不到代码时，仅对已核验目录中的公司名称/全称/别名做精确匹配，不按简称片段猜代码。多代码冲突必须核对原文，不能用客户端参数强行覆盖。

PDF 证券代码提取由 `financial_engine/security_identity.py` 区分报告主体与其他公司引用：采用封面明确代码字段、公司基本信息字段及股票简况表中的 A 股代码，排除释义及其跨页续表中的其他公司代码。多个有效主体字段发生冲突时仍拦截，不能根据请求代码强行选中其中一个。错误提示区分“多个主体代码”“代码与目标不符”和“未找到代码”。更新后身份与解析缓存使用新版本键，原缓存和历史结果不删除；此前因误识别失败的任务需在重启后端后重试。

封面名称支持中文/英文括号及常见跨行，不把“股份有限公司”等通用后缀当作公司名。联网获取时，PDF 已读取到的本公司代码必须与官方选定记录一致；满足后不再重复按全称检索。上传扩展流程也优先按 PDF 明确代码核验，而不是依赖全称搜索。若 PDF 没有可读代码，仍需通过公司名称核验，不能仅凭用户请求代码放行。证券目录查询为空或不唯一时返回中文原因。

旧结果经 `GET /api/tasks/{id}/result` 返回时可补全身份字段，不重算指标、不改写原任务快照；证券代码可同时供顶部和同行选择使用。关联任务必须具有相同文件哈希，或在没有完整哈希时具有一致的文档 ID、公司及年度，已删除或未完成任务不作为身份来源。

内置 55 家候选，身份来源和核对日期保存在 `shared/companyCatalog.json`。前后端共用该文件，部署后端时需一并保留项目根目录的 `shared` 文件夹。业务分组为人工研究分类，不是官方行业分类或可比性结论。

载入年报后，根据报告公司业务分组默认提供最多 3 家候选；同类不足时保留实际数量，名单外公司需手动添加。能源工程建设与发电运营分开提供默认候选。网页和分析接口允许 2—5 家不同同行，排除目标公司。旧历史结果保留；超过 5 家的旧配置不能直接重试，需在工作台调整。

`POST /api/tasks/{base_task_id}/peers` 将比较绑定到已完成的完整年报，年度从报告读取，复用该报告的指标、正文和历史，只获取同行报告。公司代码未识别时需确认并核对报告公司名称，不能用请求参数切换目标。`GET /api/tasks/{base_task_id}/peers` 恢复关联的已完成比较；历史回溯版本可沿同一报告任务链恢复比较。同行比较作为 `peer_compare` 派生任务保留，支持停止和从历史记录重试，不重新生成 AI 正文。

身份已核对不代表报告可下载或指标可比较。年度数据状态仅检查本机已有结果和 PDF：已保存指标、已有结果但指标不足、已有 PDF 待核验解析、上次未完成、尚无记录。搜索不会启动分析。

名单外代码核验成功后保存在 `data/companies/verified.json`；网络失败不会凭代码补造公司。公司输入支持简称片段、代码片段、拼音首字母及已收录曾用名；这属于检索联想，不是大模型预测。

### 工作台公司搜索

顶部公司选择器使用 `/api/companies` 的真实分页，显示匹配数和“加载更多”，不再固定只展示前 20 家。本地目录由内置候选、本地财报库目录和已核验的名单外公司合并；不是全 A 股名单。

`shared/companyNames.json` 保存已从原文确认的注册全称（发布时与 `companyCatalog.json` 一起保留）；已完成且公司代码无冲突的报告也可为同代码目录项补充名称别名。只用于检索和精确身份对应，不根据简称片段猜测证券代码；旧任务快照不改写。已保存名称按文件签名缓存，避免每次输入重复读取完整历史结果。

`GET /api/companies/online?q=...&report_year=2025&offset=0&limit=20` 显式读取巨潮 A 股证券目录并分页，支持证券简称、代码、拼音及已有全称/别名。官方目录只缓存一小时，不将全市场自动写入本地库、不下载财报、不调用模型。空结果返回 `total=0`；网络或目录格式错误返回 503，前端展示原因和重试入口。本地无匹配时自动尝试联网；已有候选时仍可点击“联网搜索更多公司”。这不保证尚未收录的所有注册全称、历史曾用名都能匹配，可改用证券简称或六位代码。

工作台选择候选后，提交其六位证券代码；用户改动输入即清除旧选择，必须重新选择公司。公司查询超时会明确提示，迟到响应不会覆盖新输入。年度数据状态与公司身份分开显示；“有本地 PDF”不等于分析已完成。

公开报告任务通过引擎阶段回调分别显示查找本地年报、文件校验、联网检索、下载、PDF 解析、身份核验及指标计算。进度百分比仍是任务阶段进度，不是 PDF 解析完成比例；缺少年报和联网失败分开给出中文原因。

## 历史记录与分析并发读取

历史列表通过 `history_index.py` 构建只读轻量摘要，内容不含事实明细、指标数组、完整报告或证据全文。历史 JSON 首次访问按需读取；进程内缓存最多 1024 个文件签名版本，文件修改后失效。缓存可丢弃重建，不是唯一数据源；不迁移、不删除、不改写历史分析快照。已加载任务从短临界区取得引用后，在任务锁外构建摘要；磁盘读取、身份关联、列表整理及原文件检查均不持有全局任务锁。

列表分页后仅检查当前页文件的存在性、目录归属及清单绑定，不逐条读取 PDF 做 SHA-256。`source_available` 只是可打开来源的初步提示，不是完整性认证；实际分析、原文打开仍执行原有完整校验。`GET /api/history?include_source=false` 供日志任务下拉框使用，可跳过原文件检查。结果身份补全和原文哈希验证也已移出任务锁。

历史列表请求 12 秒未完成时会显示超时及“重试读取”，暂停自动刷新并保留已加载列表。筛选变化或离开页面会取消旧请求；自动轮询不会与上一轮叠加。通用只读请求有 15 秒超时；超时不表示后台分析已停止，不会自动重发上传或新建分析任务。

`GET /api/health` 返回 `api_revision=history-isolation-1`。页面检测到旧版本会持久提示先重启后端。刷新前端不能更新正在运行的 Python 进程；重启会中断尚未完成的任务，但不会删除原文件和已完成结果。
