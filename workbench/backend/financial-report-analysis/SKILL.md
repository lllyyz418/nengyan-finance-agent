# 财务报告结构化提取与分析

Use this skill for a Chinese listed-company annual report, half-year report, or bid/investment announcement. The report adapters need a PDF text layer and read selected summary and consolidated-statement rows; the annual adapter also reads selected notes. Neither covers all notes or management discussion. Optional OCR reads selected scanned annual-summary pages into reviewable candidates and scanned announcements into event candidates. Standalone quarterly reports, other scanned financial tables, and other announcement classes need manual review; do not present a partial parse as a complete analysis.

1. Run `financial_engine.analyze_reports(file_paths)` to obtain `documents`, `facts`, `metrics`, `unavailable_metrics`, `risk_assessments`, `findings`, `warnings`, and `audit`. The PDF adapter needs the version in `requirements.txt`; `analyze_parsed_documents` uses only the Python standard library.
2. Check `warnings` and each fact's `quality` before using a number. `cross_checked` means two disclosed sections agree after unit normalization; `extracted` means one source. A conflicting, missing, or unverified field cannot support a calculation or a firm conclusion. `NOTE_ROUNDING_DIFFERENCE` reports a one-unit discrepancy in the PDF's own displayed unit; cite the disclosed total and the difference.
   For accounts-receivable aging, verify the consolidated-statement note scope and the exact `应收账款` heading. A title may be on the preceding page: `source.heading_page` then identifies the title, while `page_start` and `row_bbox` identify the value. See [SOURCE_AUDIT_CATL_2024.md](SOURCE_AUDIT_CATL_2024.md) for a corrected source mix-up.
3. Use `metrics` for arithmetic and `unavailable_metrics` for skipped formulas. Do not ask the language model to calculate growth rates or ratios or treat `null` as zero. Read [FORMULAS.md](FORMULAS.md) before explaining an indicator's definition, precision, or limitation. Preserve the reported raw value and unit alongside the normalized CNY value.
4. Tie each statement to `fact_id` or `metric_id`. Use `sources` for the PDF page, original value and unit, and row bounding box; resolve `source.document_id` against `documents` for the full PDF SHA-256. For a split row, use `parts` to show each page fragment. Distinguish a reported fact, a computed value, and a screening signal.
5. Read [RISK_RULES.md](RISK_RULES.md) when explaining a risk assessment. Show each rule's `status`, observed conditions, missing inputs and limitations. Treat `findings` as prompts for further review; a triggered rule does not prove fraud or supply an investment rating. `not_evaluated` means this parser has not covered the relevant disclosure.
   For receivables aging, show the percentage-point gaps and distinguish age from contractual overdue days. The original risk check is documented in [RISK_SIGNAL_AUDIT.md](RISK_SIGNAL_AUDIT.md); the peer field repair is documented in [PEER_EXTRACTION_AUDIT.md](PEER_EXTRACTION_AUDIT.md).
6. Keep government-grant categories separate. "Other income", grant income in other income, deferred grant balances, and grants in nonrecurring gains are distinct disclosures. An unitemized other-income total does not establish a grant amount.
7. For annual history, use `financial_engine.analyze_company_history(...)` with a cache directory chosen by the host application. Read [HISTORY.md](HISTORY.md) for online and offline calls, report-version selection, `history.fact_series`, `history.series`, cross-year `changes`, and restatement checks. Show retrieval failures and withheld comparisons. Do not treat a downloaded report or an inferred security code as proof that the uploaded file is authentic.
8. For a same-year peer comparison, require an explicit company list, business group and selection rationale; use `financial_engine.analyze_peer_group(...)` or `compare_peer_group(...)`. Read [PEERS.md](PEERS.md) for input and output details. Compare only sourced metrics with the same formula, unit and reporting period. Treat the peer median as a small-sample description, and explain material business-mix limitations before drawing conclusions.
9. For an investment, expansion, or bid notice, call `financial_engine.analyze_announcement(...)`, separately from `analyze_reports`. Read [ANNOUNCEMENTS.md](ANNOUNCEMENTS.md) for public-catalogue discovery, optional OCR, currencies, role-specific amounts, coordinates, and review status. Never place announcement amounts into annual `facts` or ratio inputs. Show the original line and page when describing a candidate, and preserve "about", "up to", unsigned-contract, and OCR qualifiers.
10. For a half-year report, use `financial_engine.analyze_semiannual_reports(...)` and read [SEMIANNUAL.md](SEMIANNUAL.md). Treat H1 flows as January–June cumulative values and stock balances as June 30 versus prior December 31; do not reuse annual growth or return periods. Preserve `assurance`, comparative restatement flags, and unavailable-metric reasons. The annual history and peer functions remain annual-only.
11. For one call that retrieves annual history and configured peers, use `financial_engine.analyze_disclosure_context(...)` and read [DATA_MINING.md](DATA_MINING.md). Accept an uploaded PDF or an explicit company code and fiscal year. Network access is opt-in; show file coverage, cache-only version selection, code conflicts, and rejected documents. Resolve comparison evidence in the appropriate history or peer sub-analysis. This entry retains H1 current analysis but does not compare H1 reports. Read [CONTEXT_RISK.md](CONTEXT_RISK.md) for `risk_review`: a source-basis conflict blocks persistent-risk claims, and peer margin screens require two valid configured peers. Keep data-quality differences separate from operating risk.
12. If the host needs one-file routing, use `financial_engine.analyze_uploaded_document(...)`. Its nested `analysis` is the matching specialist result. It does not crawl, select peers, or perform model orchestration; the host can call history, peer and announcement functions separately when authorized and relevant.
13. For selected scanned annual-summary pages, use `financial_engine.analyze_scanned_financial_pages(...)` and read [SCANNED_FINANCIAL.md](SCANNED_FINANCIAL.md). Treat `machine_checked` as an OCR candidate with internal percentage/quarter reconciliation, not as an audited fact. Its top-level review status remains `requires_human_review`. Preserve the page, bbox, confidence and failed checks.
14. To analyze explicitly human-confirmed scan candidates, read [SCAN_REVIEW.md](SCAN_REVIEW.md). `create_scan_review_template` leaves every decision pending; the host obtains actual human review and authenticates the reviewer. Never fabricate a review or declare model output to be human confirmation. `analyze_reviewed_scan` rechecks the source PDF hash, candidate snapshot, identity, units and conflicts before calling existing formulas/rules on the admitted subset. Its nested `analysis` contains the existing financial contract. Show pending/rejected/conflicting input reasons and incomplete risk coverage; no risk finding does not imply no risk.

For the JSON contract and an integration example, read [INTEGRATION.md](INTEGRATION.md). The host Agent must persist the returned `audit` events with its own file access, tool call, and model call logs.
